# 标准 Agent Skills 运行设计

| 属性 | 内容 |
| --- | --- |
| 文档角色 | 规范性 |
| 适用范围 | Pi 员工发现、启用和使用标准 Agent Skills 的行为 |
| 标准基线 | Agent Skills 正式规范，2026-08-23 核对 |

## 1. 产品结论

AI Corporation 使用标准 Agent Skills 文件夹作为员工能力的主要封装方式，不再为每种员工能力另外发明一套私有格式。

用户已确认：

- 一名员工可以拥有多项 Skill，Skill 只对被分配的员工可见；
- 用户直接交代任务，员工根据 Skill 的名称和用途自动选择，不要求用户每次手工指定；
- Skill 的完整说明、参考资料、脚本和资源按需加载，不在任务开始时全部塞给模型；
- 软件使用专门的 Skill 工具读取参考资料、复制资源和运行脚本；
- 缺少环境时提供明确说明和“自动安装”选项；当前由环境管理工具执行，未来多员工能力完成后，可增加环境员工复用同一工具；
- 自动安装默认进入 Skill 独立环境，只有 Skill 明确要求时才进入项目环境；修改系统环境必须再次明确确认；
- JavaScript 使用软件自带运行能力，Python 缺失时由软件安装到自管目录；Windows 原生脚本使用 PowerShell，macOS 原生脚本使用 Shell。

## 2. 标准边界

一个 Skill 至少包含根目录下的 `SKILL.md`。软件按正式规范处理：

- 必需字段：`name`、`description`；
- 可选字段：`license`、`compatibility`、`metadata`、`allowed-tools`；
- `scripts/`、`references/`、`assets/` 和其他文件均属于 Skill 自管资源；
- `name` 必须与父目录名一致，并满足小写字母、数字和连字符规则；
- `allowed-tools` 是实验字段，只作为来源信息显示，不能批准 AI Corporation 的工具或命令。

AI Corporation 只从用户明确导入后形成的应用自管副本运行 Skill。当前不自动扫描工作区或用户目录，也不直接运行来源目录中的文件。

## 3. 渐进加载

运行分三层：

1. **技能目录**：任务开始时只给模型员工已分配 Skill 的 `name + description`；
2. **完整说明**：模型判断某项 Skill 与任务匹配后，调用 `skill.activate` 加载其完整 `SKILL.md`；
3. **按需资源**：只有说明真正引用某个文件时，才调用资源工具列出、读取、复制或运行。

未启用的 Skill 不把完整说明放入模型上下文。模型不能启用未分配给当前员工的 Skill。每次启用、读取和复制都进入用户可展开的工具过程。

## 4. 多 Skill 员工

- 员工至少拥有一项 Skill，可以拥有多项；
- 现有员工升级时，原 `skillName` 迁移为技能列表中的唯一一项，不要求用户重建员工；
- Skill 分配是员工定义的一部分，不因加入不同公司而改变；
- 同名 Skill 更新后，员工继续绑定该名称并使用应用自管的当前版本；
- 删除、损坏或不可用的 Skill 不得被静默替换，开始任务时显示准确原因和恢复入口。

## 5. Skill 工具

### 5.1 `skill.activate`

输入 Skill 名称。软件核对当前员工分配后，返回去掉头部元数据的完整说明和 Skill 的逻辑名称。不得向 Renderer 或模型暴露应用内部绝对路径。

### 5.2 `skill.list_resources`

列出已启用 Skill 的 `references/`、`assets/` 和 `scripts/` 中可用的相对路径、类型、大小与当前平台运行状态。列表不能跟随链接，也不能泄漏绝对路径。支持 `.js/.mjs/.cjs/.py`，Windows 额外支持 `.ps1`，macOS 额外支持 `.sh`；其他类型明确标记不支持。

### 5.3 `skill.read_resource`

读取已启用 Skill 的 `references/` 中普通 UTF-8 文本。只接受相对路径，拒绝绝对路径、`..`、链接、目录、二进制和超限文件。

### 5.4 `skill.copy_asset`

把已启用 Skill 的 `assets/` 文件复制到当前任务工作区。源路径和目标路径分别重新核对，写入沿用工作区并发保护和成果登记；不得覆盖并发变化，也不得把未复制成功的资源显示成成果。

### 5.5 `skill.run_script`

运行 `scripts/` 下的脚本。模型只提交 Skill 名称、脚本相对路径、参数、可选结构化依赖和可选预期成果相对路径，不能提交可执行程序、shell 命令、工作目录、环境变量或应用内部绝对路径。

每次调用重新核对员工分配、Skill 已启用、脚本路径、链接和内容摘要。脚本从该 Skill 的运行副本根目录启动，保持标准 Skill 的相对路径语义。JavaScript 使用应用 Node 模式，Python 使用独立环境解释器，PowerShell 和 Shell 使用当前平台原生程序；所有调用都使用“程序 + 参数”的结构化启动，不拼接 shell 命令。

`skill.run_script` 会先调用同一环境准备逻辑；已经就绪就直接进入任务脚本授权，缺少内容就先展示安装计划。安装批准和脚本执行授权相互独立。脚本 stdout、stderr、退出码、耗时、截断和错误进入现有工具过程；零退出码不能代替真实成果核对。

### 5.6 `skill.run_workspace_script`

运行员工已经写入当前 Workspace 的普通 Python 脚本，并让脚本使用一项已启用 Skill 的独立环境和只读运行副本。该工具用于公开 Skill 只提供可导入库、没有 `scripts/` 入口的真实情况；它不能把工作区里的任意程序包装成通用执行权限。

模型只提交 Skill 名称、工作区脚本相对路径、可选结构化依赖、参数和预期成果相对路径，不能提交可执行程序、shell 命令、工作目录、环境变量或应用内部绝对路径。当前只支持 `.py`；其他工作区脚本运行程序由后续独立任务处理。

每次调用都重新核对公司、员工、任务、Workspace、Skill 分配和启用状态，并通过 Native Core 读取当前脚本内容与摘要，拒绝绝对路径、`..`、链接、目录、二进制、超限文件和并发变化。软件把已核对脚本复制到该环境的一次性私有运行目录，以 Workspace 为工作目录启动 Python，并在内部设置只指向该 Skill 运行副本的模块搜索路径；运行结束后删除一次性脚本。模型、Renderer、日志和错误只显示逻辑名称与相对路径。

环境准备、安装批准、运行批准、过程展示、取消、超时、重启恢复和成果核对全部沿用 `skill.run_script` 的边界。安装批准不能代替运行批准，脚本零退出码也不能代替预期成果的真实核对。

## 6. 环境管理

环境管理使用 `environment.prepare` / `environment_prepare`：

- JavaScript 使用应用自带 Node 与 npm；Python 使用随包固定 uv，解释器与虚拟环境只安装到应用自管目录；
- 自动识别 PEP 723、Skill 根 `requirements.txt` 与 `package.json`。模型补充项只允许生态、包名和版本，不接受命令、URL、Git 地址、本地路径或包管理器参数；
- 默认以 Skill 内容、平台、架构、运行程序和依赖摘要建立 `SKILL` 独立环境，可跨任务和公司复用；Skill 或依赖变化后使用新环境；
- 只有 Skill 明确要求并给出原因时才使用当前 Workspace 的 `PROJECT` 环境；项目环境不登记为任务成果；
- 缺失时显示名称、用途、来源、安装位置类型、精确命令、网络、包安装脚本风险和系统影响；用户可选择“自动安装”或“暂不安装”；
- 独立环境安装单独批准。缺少系统程序时只允许受限 winget/Homebrew 计划，并再次确认精确软件和命令；管理器不存在时只给人工办法；
- 安装先写临时目录，复检真实通过后再原子提交 `READY` 清单；原任务随后继续，不要求用户重新输入任务；
- 安装中断、失败、超时、结果未知或复检失败不得显示成功、不得运行脚本，也不得自动重复执行。

当前不创建环境员工。未来环境员工只能调用同一环境管理工具，不能绕过审批或获得额外权限。

## 7. 任务拆分

- `M12-TU-01`：标准解析、多 Skill 分配、自动启用、参考资料读取和资源复制；
- `M12-TU-02`：脚本运行、环境检查、隔离自动安装、系统安装再确认和恢复；
- `M13-TU-01`：导入未经修改的真实公开 `slack-gif-creator`，通过工作区 Python 脚本桥接其 `core/`，完成真实 GIF 生成、核对、预览和最终安装包验收。

前一个任务通过不代表脚本和自动安装已交付；两个任务都通过后，Milestone 12 才能关闭。

## 8. 安全与恢复

- Skill、参考资料、脚本和资源均是不可信外部内容，不能改变系统规则、审批边界或 API Key 处理；
- 导入和分配 Skill 不产生执行授权；
- Skill 工具调用固定属于当前公司、员工、任务和工作区；
- 应用重启不自动重新启用模型轮次、不重复复制资源、不重复运行脚本或安装环境；
- 导入更新、资源复制、脚本和环境安装都必须有可核对的提交记录或结果事实；运行中断的进程标记为 `UNKNOWN`；
- API Key、Key Vault 和应用认证秘密不进入脚本或安装进程；脚本以用户当前 OS 账户运行，当前没有 OS 级强沙箱，批准卡必须如实说明；
- 应用自管 Skill/环境绝对路径不返回模型或 Renderer。逻辑 Workspace 位置由 Main 转换，成果仍通过 Workspace 可信边界核对。

Tool Registry 使用上面的点号 ID；提供给 Pi 模型的函数名分别使用 `skill_activate`、`skill_list_resources`、`skill_read_resource`、`skill_copy_asset`、`skill_run_script` 和 `skill_run_workspace_script`，避免不同层各自发明名字。
