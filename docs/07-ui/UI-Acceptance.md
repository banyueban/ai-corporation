# AI Corporation Desktop v0.1 UI 验收标准

## 1. 文档地位

本文档定义 UI 专项验收要求。[统一验收标准](../06-engineering/Acceptance-Standard.md)仍是项目唯一验收入口；实现 UI 功能时，从统一标准进入并引用本文档。

## 2. 需求追踪

每个屏幕或交互必须关联：

- PRD FR/NFR/AC；
- 本目录对应流程、线框和状态矩阵；
- 领域实体和状态；
- 自动化或人工验收证据。

## 3. UI Definition of Done

### 3.1 结构

- [ ] 页面信息层级符合 Information Architecture；
- [ ] 主操作在当前上下文唯一明确；
- [ ] 用户可在三步内到达待审批项；
- [ ] Corporation 内始终保留返回 Dashboard 的路径；
- [ ] 深层详情不丢失 Task/Corporation 上下文。

### 3.2 状态

- [ ] 实现 Screen State Matrix 中适用状态；
- [ ] Loading、Empty、Error、Degraded 不混用；
- [ ] 领域状态由真实数据驱动；
- [ ] 暂停、取消、恢复和迟到响应有明确行为；
- [ ] 未知副作用不会显示为成功或可自动重试；
- [ ] 进度明确标记估算。

### 3.3 安全

- [ ] 审批展示精确动作、资源、风险和副作用；
- [ ] 高风险动作没有默认永久授权；
- [ ] 请求内容变化后旧审批失效；
- [ ] 文件写入可查看 Diff；
- [ ] 命令以 executable + args 展示；
- [ ] API Key 只在用户主动录入的专用密码输入框中短暂存在并默认遮挡；提交后清空，已存 Key 不回填 Renderer，也不出现在截图、日志、错误或诊断 UI；
- [ ] 外部内容不能改变审批按钮和 Policy。

### 3.4 可访问性

- [ ] 完整键盘导航；
- [ ] 焦点顺序合理且可见；
- [ ] 模态焦点陷阱和返回正确；
- [ ] 状态不只用颜色表达；
- [ ] 对比度满足 WCAG AA；
- [ ] 200% 缩放仍可完成核心流程；
- [ ] reduced motion 生效；
- [ ] 表单错误可由辅助技术关联；
- [ ] 图标按钮有名称。

### 3.5 响应与桌面适配

- [ ] 1440 × 900 基准布局正确；
- [ ] 1024 × 700 最小窗口可完成核心任务；
- [ ] 右栏可收缩为抽屉；
- [ ] 审批关键信息不因收缩被隐藏；
- [ ] Windows/macOS 窗口控制区不被遮挡；
- [ ] 高 DPI 和系统缩放无严重错位。

### 3.6 性能

- [ ] 普通交互 P95 目标 ≤ 150ms；
- [ ] 页面切换不因同步 SQLite/文件读取阻塞；
- [ ] 10,000 条 Timeline 使用虚拟化；
- [ ] 大 Artifact 分块/虚拟化；
- [ ] 空闲 UI 不持续轮询；
- [ ] Spinner 超时后提供诊断或取消。

### 3.7 文案

- [ ] 错误说明发生事项、影响和恢复动作；
- [ ] 危险按钮包含具体结果；
- [ ] 不用拟人化语言掩盖责任；
- [ ] 不使用“基本完成”“马上完成”等不精确状态；
- [ ] Provider/Token 等技术信息默认位于详情层。

## 4. 核心 UI 验收场景

### UI-AC-01 首次设置

1. 输入 Provider 配置；
2. Key 写入安全存储；
3. 连接成功进入 Dashboard；
4. 认证失败不泄露 Key；
5. 安全存储失败时不允许明文降级。

### UI-AC-02 创建与计划

1. 选择工作区；
2. 输入目标；
3. 审阅 Goal Contract；
4. 确认高影响假设；
5. 查看任务、依赖、团队、预算和风险；
6. 启动 Corporation。

### UI-AC-03 观察和暂停

1. Workspace 显示真实当前 Task；
2. 用户点击暂停；
3. UI 进入 Pausing；
4. 安全检查点后进入 Paused；
5. 用户可继续且不重复已提交副作用。

### UI-AC-04 写入审批

1. 展示请求者、Task、精确路径和 Diff；
2. 默认选择“仅本次”；
3. 批准后按钮不可重复提交；
4. 请求 fingerprint 改变时旧批准失效；
5. 拒绝后显示 Task 后续行为。

### UI-AC-05 验收失败与修订

1. 显示 REQUIRED 失败项；
2. 每项包含 Evidence；
3. 显示修订次数；
4. 可比较新旧版本；
5. 到达上限后请求人工，不无限循环。

### UI-AC-06 崩溃恢复

1. 启动时检测中断；
2. 对未知副作用显示阻断恢复页；
3. 不默认自动重试；
4. 用户选择留下审计事件；
5. Dashboard/Workspace 恢复正确状态。

### UI-AC-07 最终交付

1. 成功标准逐项显示；
2. 交付物可打开；
3. Evidence 可追溯；
4. 已知限制可见；
5. 成本和耗时标识估算/实报；
6. 可导出 Markdown 报告。

## 5. 自动化证据

最低要求：

- React 组件状态测试；
- 路由与状态映射测试；
- Approval 交互测试；
- 键盘和焦点测试；
- axe 或等价可访问性扫描；
- Electron E2E；
- 1024 × 700 与 1440 × 900 截图回归；
- Windows/macOS 冒烟；
- Timeline 和大 Artifact 性能测试。

## 6. 人工验收证据

需要人工检查：

- 信息层级是否清晰；
- 风险文案是否准确；
- 键盘全流程；
- 200% 缩放；
- 屏幕阅读器关键流程；
- Windows/macOS 原生窗口行为；
- 审批是否可能被误解；
- 真实长目标、长路径和多 Task 数据。

## 7. 阻断缺陷

以下是 UI 领域的 P0/P1 示例；等级定义和阻断门槛只以[统一验收标准](../06-engineering/Acceptance-Standard.md)为准：

- 未审批即可触发副作用；
- UI 显示的资源与实际执行资源不同；
- 已存 API Key 被回传/回填到 Renderer，或 Key 出现在输入框以外的 Renderer 状态、日志、错误、截图或诊断 UI；
- WAITING_HUMAN 被错误显示为继续执行；
- 重复点击造成重复调用；
- 崩溃恢复默认重放未知副作用；
- 错误状态仍显示“已完成”；
- 键盘无法处理关键审批；
- 最小窗口无法看到危险动作的完整影响。

## 8. 线框到实现的偏差

允许在实现中调整：

- 精确尺寸；
- 组件排列细节；
- 文案微调；
- 非关键图标；
- 技术上必要的渐进加载。

必须记录并评审：

- 导航层级变化；
- 核心主操作变化；
- 审批信息减少；
- 状态含义变化；
- 隐藏证据或已知限制；
- 增加 v0.1 范围；
- Windows/macOS 行为分叉。
