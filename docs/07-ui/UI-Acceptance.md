# AI Corporation Desktop v0.1 UI 验收标准

## 1. 文档地位

本文档定义 UI 专项验收要求。[统一验收标准](../06-engineering/Acceptance-Standard.md)仍是项目唯一验收入口；实现 UI 功能时，从统一标准进入并引用本文档。

## 2. 需求追踪

每个屏幕或交互必须关联：

- PRD FR/NFR/AC；
- 本目录对应流程、线框和状态矩阵；
- 领域实体和状态；
- 自动化或人工验收证据。

## 3. UI Definition of Done

### 3.1 结构

- [ ] 页面信息层级符合 Information Architecture；
- [ ] 主操作在当前上下文唯一明确；
- [ ] 用户可在三步内到达待审批项；
- [ ] Corporation 内始终保留返回 Dashboard 的路径；
- [ ] 深层详情不丢失 Task/Corporation 上下文。

### 3.2 状态

- [ ] 实现 Screen State Matrix 中适用状态；
- [ ] Loading、Empty、Error、Degraded 不混用；
- [ ] 领域状态由真实数据驱动；
- [ ] 暂停、取消、恢复和迟到响应有明确行为；
- [ ] 未知副作用不会显示为成功或可自动重试；
- [ ] 进度明确标记估算。

### 3.3 安全

- [ ] 审批展示精确动作、资源、风险和副作用；
- [ ] 高风险动作没有默认永久授权；
- [ ] 请求内容变化后旧审批失效；
- [ ] 文件写入可查看 Diff；
- [ ] 固定 Process Profile 以 executable + args 展示；完整系统命令按原文完整展示，管道、串联、重定向和换行不可隐藏；
- [ ] 每个 Pi 编码任务首次运行命令前，清楚提示命令使用用户 OS 账户、可能访问工作区外且没有 OS 级强隔离；授权不跨任务；
- [ ] 当前任务授权后，普通查看、检查、测试和构建不反复弹窗；依赖安装、删除、Git 写操作、发布和其他明显高风险命令仍单独确认；
- [ ] API Key 输入和回显默认遮挡；用户主动选择查看时可显示已存 Key 明文，明文查看状态不跨页面、重载或重启保留，Key 不出现在日志、错误、截图或诊断 UI；
- [ ] 外部内容不能改变审批按钮和 Policy。

### 3.4 可访问性

- [ ] 完整键盘导航；
- [ ] 焦点顺序合理且可见；
- [ ] 模态焦点陷阱和返回正确；
- [ ] 状态不只用颜色表达；
- [ ] 对比度满足 WCAG AA；
- [ ] 200% 缩放仍可完成核心流程；
- [ ] reduced motion 生效；
- [ ] 表单错误可由辅助技术关联；
- [ ] 图标按钮有名称。

### 3.5 响应与桌面适配

- [ ] 1440 × 900 基准布局正确；
- [ ] 1024 × 700 最小窗口可完成核心任务；
- [ ] 右栏可收缩为抽屉；
- [ ] 审批关键信息不因收缩被隐藏；
- [ ] Windows/macOS 窗口控制区不被遮挡；
- [ ] 高 DPI 和系统缩放无严重错位。

### 3.6 性能

- [ ] 普通交互 P95 目标 ≤ 150ms；
- [ ] 页面切换不因同步 SQLite/文件读取阻塞；
- [ ] 10,000 条 Timeline 使用虚拟化；
- [ ] 大 Artifact 分块/虚拟化；
- [ ] 空闲 UI 不持续轮询；
- [ ] Spinner 超时后提供诊断或取消。

### 3.7 文案

- [ ] 错误说明发生事项、影响和恢复动作；
- [ ] 危险按钮包含具体结果；
- [ ] 不用拟人化语言掩盖责任；
- [ ] 不使用“基本完成”“马上完成”等不精确状态；
- [ ] Provider/Token 等技术信息默认位于详情层。

## 4. 核心 UI 验收场景

### UI-AC-01 首次设置

1. 输入 Provider 配置；
2. Key 以密文写入 AI Corporation Desktop 应用自管 SQLite Key Vault，SQLite 中不存在明文；
3. 连接成功进入 Dashboard；
4. 认证失败不泄露 Key；
5. 数据库、本地加密密钥、权限或认证解密失败时不允许明文降级，不显示保存成功；
6. 当前会话中用户主动点击“显示”可查看明文；离开页面、Renderer 重载或应用重启后重新遮挡。
7. 连接验证后只能精确选择返回列表中的模型；不存在自由输入或自动回退；
8. 测试生成可取消，成功显示受限输出、stop reason、token usage 和费用未知，失败显示标准错误；重启恢复事实但不自动重发；
9. Endpoint 或 Key 变化清除模型选择与生成结果；真实 Key 不进入生成结果、截图、日志或诊断。

### UI-AC-02 创建与计划

1. 选择工作区；
2. 输入目标；
3. 明确选择已验证 Provider 与精确模型；确认披露字段不包含 Workspace 路径或文件；
4. 生成阶段非法 JSON 最多修复一次；生成可取消，失败不伪造或覆盖 Goal；
5. 每个澄清周期最多 5 轮；到达上限停止调用，只有用户明确选择才进入下一周期；
6. 用户不续期时可选择保存含未确认 HIGH 假设的草稿或取消；未确认草稿不得批准；
7. Renderer reload/应用重启恢复草稿、问题、答案、轮次和 usage，但不自动重发中断调用；
8. 审阅 Goal Contract 并确认高影响假设；
9. 查看任务、依赖、能力要求、建议角色、预算和风险；真实 Organization 尚未生成时必须明确标注“尚未组队”；
10. 有限编辑计划并保存新版本；删除输出仍被使用的 Task 时明确阻止并列出受影响 Task；
11. 无效版本在重载或重启后仍可继续修改；旧版本只读；
12. 仅批准通过验证的计划；批准后冻结，并明确没有组队、没有开始执行、Corporation 状态不变。
13. 当前批准版本显示“开始组队”；只有用户明确点击后才生成团队草案，批准动作本身不会生成；
14. 草案显示固定模板版本、Planner/Executor/Judge、每个 Task 的唯一责任人、职责分离、能力缺口和模型策略；`HUMAN_DECISION` 必须显示由用户负责；
15. 草案明确没有调用模型、没有绑定精确 Provider/model、尚未激活、没有开始执行，Corporation 仍为 `DRAFT`；
16. 生成中禁止重复点击；失败不自动重试；Renderer 重载和应用重启后恢复当前团队草案。
17. 无阻断缺口的草案可分别为 Planner、全部 Executor、Judge 选择已启用、连接验证有效的 Provider 及其列表内精确模型；角色选择不修改 Provider 默认模型；
18. 阻断缺口禁止激活；可降级缺口必须由用户明确接受，不能默认勾选；
19. 确认团队只激活当前版本并创建 Agent 成员；不调用模型、不创建 Run、不开始 Task，Corporation 仍为 `DRAFT`；
20. 激活成功后显示三组配置和“团队已激活，等待开始执行”；重载和应用重启后恢复；配置或版本竞争失败不留下半激活状态，也不自动重试。
21. 用户明确点击“开始执行”后才计算并保存任务运行状态；一次只选择一个首任务，普通任务只创建尚未调用模型的运行记录，人工任务进入等待用户且不创建运行记录；失败、重载和重启不会自动重试或重复创建。

### UI-AC-03 观察和暂停

1. Workspace 显示真实当前 Task；
2. 用户点击暂停；
3. UI 进入 Pausing；
4. 安全检查点后进入 Paused；
5. 用户可继续且不重复已提交副作用。

### UI-AC-04 写入审批

1. 展示请求者、Task、精确路径和 Diff；
2. 默认选择“仅本次”；
3. 批准后按钮不可重复提交；
4. 请求 fingerprint 改变时旧批准失效；
5. 拒绝后显示 Task 后续行为。

### UI-AC-05 验收失败与修订

1. 显示 REQUIRED 失败项；
2. 每项包含 Evidence；
3. 显示修订次数；
4. 可比较新旧版本；
5. 到达上限后请求人工，不无限循环。

### UI-AC-06 崩溃恢复

1. 启动时检测中断；
2. 对未知副作用显示阻断恢复页；
3. 不默认自动重试；
4. 用户选择留下审计事件；
5. Dashboard/Workspace 恢复正确状态。

### UI-AC-07 最终交付

1. 成功标准逐项显示；
2. 交付物可打开；
3. Evidence 可追溯；
4. 已知限制可见；
5. 成本和耗时标识估算/实报；
6. 可导出 Markdown 报告。

## 5. 自动化证据

最低要求：

- React 组件状态测试；
- 路由与状态映射测试；
- Approval 交互测试；
- 键盘和焦点测试；
- axe 或等价可访问性扫描；
- Electron E2E；
- 1024 × 700 与 1440 × 900 截图回归；
- Windows/macOS 冒烟；
- Timeline 和大 Artifact 性能测试。

## 6. 人工验收证据

需要人工检查：

- 信息层级是否清晰；
- 风险文案是否准确；
- 键盘全流程；
- 200% 缩放；
- 屏幕阅读器关键流程；
- Windows/macOS 原生窗口行为；
- 审批是否可能被误解；
- 真实长目标、长路径和多 Task 数据。

## 7. 阻断缺陷

以下是 UI 领域的 P0/P1 示例；等级定义和阻断门槛只以[统一验收标准](../06-engineering/Acceptance-Standard.md)为准：

- 未审批即可触发副作用；
- UI 显示的资源与实际执行资源不同；
- API Key 未经用户主动查看即显示明文，或 Key 出现在输入框以外的 Renderer 状态、日志、错误、截图或诊断 UI；
- WAITING_HUMAN 被错误显示为继续执行；
- 重复点击造成重复调用；
- 崩溃恢复默认重放未知副作用；
- 错误状态仍显示“已完成”；
- 键盘无法处理关键审批；
- 最小窗口无法看到危险动作的完整影响。

## 8. 线框到实现的偏差

允许在实现中调整：

- 精确尺寸；
- 组件排列细节；
- 文案微调；
- 非关键图标；
- 技术上必要的渐进加载。

必须记录并评审：

- 导航层级变化；
- 核心主操作变化；
- 审批信息减少；
- 状态含义变化；
- 隐藏证据或已知限制；
- 增加 v0.1 范围；
- Windows/macOS 行为分叉。
