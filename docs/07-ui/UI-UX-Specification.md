# AI Corporation Desktop v0.1 UI/UX 总体规范

## 1. 体验目标

AI Corporation Desktop 的界面不模拟办公室，也不把 Agent 包装成娱乐化角色。界面必须帮助用户持续回答五个问题：

1. 我的目标是什么；
2. 系统现在处于什么状态；
3. 当前正在执行什么，为什么；
4. 是否需要我做决定；
5. 最终交付物是否经过验证。

## 2. 体验原则

### UX-01 目标优先

Corporation 名称、目标摘要和成功标准始终比 Agent 形象更突出。任何页面都能回到 Goal Contract。

### UX-02 状态必须真实

只显示领域状态，不使用“马上完成”“正在深度思考”等无法验证的措辞。百分比进度明确标记为估算。

### UX-03 默认展示摘要，证据可深入

第一层展示结论、阻塞和下一步；第二层提供 Task、Artifact、工具调用、评价和成本证据。

### UX-04 高风险动作减速

文件覆盖、删除、命令、预算追加等操作不能用普通确认 Toast 处理。必须使用阻断式审批界面，展示精确目标和后果。

### UX-05 失败可行动

错误信息至少包含：

- 发生了什么；
- 影响了什么；
- 系统是否已安全停止；
- 用户可以执行什么；
- 诊断详情入口。

### UX-06 人工控制始终可见

执行期间始终提供暂停入口。取消、扩大权限和追加预算必须与普通操作区分。

### UX-07 Artifact 是主要交付对象

Agent 输出不能只出现在聊天气泡里。所有重要结果进入 Artifact 视图，具备版本、状态、来源和评价。

### UX-08 不把内部实现暴露为主交互

Provider、Token、调用 ID、Schema 等默认在详情层；主界面使用目标、任务、交付物、审批和风险语言。

## 3. 产品心智模型

```text
Corporation
├── Goal Contract：要完成什么
├── Plan：怎样完成
├── Team：谁负责
├── Work：当前进展
├── Artifacts：产生了什么
├── Evaluations：是否合格
└── Timeline：发生过什么
```

UI 中避免同时使用 Project、Company、Session 等近义词。面向用户统一使用：

- 中文：任务组织 / Corporation（首次出现可解释）；
- 内部英文实体：Corporation；
- 单步工作：Task；
- 交付成果：Artifact。

## 4. 桌面窗口基线

### 4.1 尺寸

- 推荐窗口：1440 × 900；
- 最小可用窗口：1024 × 700；
- 小于最小尺寸时不压缩关键审批信息，允许内容区滚动；
- 不为移动端设计；
- 支持 100%–200% 系统缩放。

### 4.2 区域

```text
┌──────────────────────────────────────────────────────────┐
│ Native title bar / draggable region                      │
├──────────────┬───────────────────────────────────────────┤
│ App sidebar  │ Page header                               │
│              ├───────────────────────────────────────────┤
│              │ Main content                              │
│              │                                           │
│              ├───────────────────────────────────────────┤
│              │ Optional details drawer                   │
└──────────────┴───────────────────────────────────────────┘
```

- App sidebar：220–248px，可收起；
- Page header：64px 左右；
- 内容最大宽度不强制固定，表格和任务视图可扩展；
- 详情抽屉宽度 400–520px；
- 模态框只用于阻断决策，不用于日常浏览。

## 5. 导航模型

### 5.1 全局导航

- Dashboard；
- Running（有活跃 Corporation 时显示数量）；
- Approvals（有待审批时显示高优先级徽标）；
- Settings。

### 5.2 Corporation 内导航

- Overview；
- Plan；
- Team；
- Artifacts；
- Timeline；
- Settings。

选择 Corporation 后，侧栏保留返回 Dashboard 的明确入口。

### 5.3 深层对象

Task、Artifact、Agent Run、Evaluation 和 Tool Invocation 使用详情抽屉或专用详情页。浏览历史时不丢失当前 Corporation 上下文。

## 6. 主状态语言

| 领域状态 | 用户标签 | 颜色语义 | 主操作 |
|---|---|---|---|
| DRAFT | 草稿 | 中性 | 继续配置 |
| PLANNING | 正在规划 | 信息 | 暂停 |
| ORGANIZING | 正在组建团队 | 信息 | 暂停 |
| EXECUTING | 正在执行 | 信息/活动 | 暂停 |
| VERIFYING | 正在验收 | 信息 | 暂停 |
| WAITING_HUMAN | 等待你的决定 | 警告 | 查看并处理 |
| PAUSED | 已暂停 | 中性 | 继续 |
| COMPLETED | 已完成 | 成功 | 查看交付 |
| FAILED | 执行失败 | 危险 | 查看原因 |
| CANCELLED | 已取消 | 中性 | 查看记录 |
| ARCHIVED | 已归档 | 中性弱化 | 恢复/查看 |

状态标签不能只依靠颜色，必须包含文本和图标。

## 7. 进度与预算

### 7.1 进度

- 显示已完成 Task 数量，如 `4 / 7`；
- 可显示估算百分比，但附“估算”；
- WAITING_HUMAN 时进度条停止动画；
- 不用循环动画假装任务持续前进；
- 关键路径和当前 Task 比百分比更突出。

### 7.2 预算

顶部预算组件显示：

```text
¥ / $ 0.42 / 2.00
Tokens 18k / 100k
Time 12m / 60m
```

- 80%：警告；
- 100%：停止新调用并显示阻断状态；
- 追加预算需说明增量和新的硬上限；
- 费用为估算时明确标识。

## 8. 通知策略

| 类型 | 表现 |
|---|---|
| 普通成功 | 非阻断 Toast，可自动消失 |
| 普通错误 | 持久 Toast + 详情入口 |
| 待审批 | 全局徽标 + Corporation 内阻断卡片；可发系统通知 |
| Corporation 完成 | 系统通知 + Dashboard 状态 |
| 预算 80% | 警告 Banner |
| Provider 退化 | 页面 Banner，不连续弹窗 |
| 数据/副作用不确定 | 阻断式恢复界面 |

Toast 不能承载必须记住的信息。

## 9. 文案规范

- 使用动作和结果：“无法读取文件”，不写“发生未知错误”；
- 使用精确对象：“将修改 `docs/PRD.md`”；
- 不拟人化推卸责任：“系统未能验证”，不写“测试员 Agent 不高兴”；
- 风险文案不弱化：“此命令可能修改 12 个文件”；
- 主按钮使用动词：“开始执行”“批准本次写入”“继续恢复”；
- 危险按钮包含结果：“取消并停止任务”“删除内部记录”。

## 10. 可访问性

- 所有交互可用键盘完成；
- 明确焦点环；
- 模态打开后焦点进入，关闭后返回触发点；
- 表单错误与字段通过 `aria-describedby` 关联；
- 状态变化使用适度的 live region；
- 文本和关键图标满足 WCAG AA 对比度；
- 不用颜色单独表达状态；
- 支持减少动画；
- 图表有文本替代；
- 触控目标不小于 32 × 32px，主要按钮不小于 40px 高。

## 11. v0.1 非目标

- 虚拟办公室和 Agent 头像漫游；
- 自由拖拽 DAG 编辑器；
- 多窗口复杂工作台；
- 移动端响应式；
- 自定义主题编辑器；
- 插件注入任意 UI；
- 实时 Token 流作为默认主视图；
- 面向营销的动画与 3D。
