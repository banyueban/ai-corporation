## 1. 需求与设计引用

- 用户于 2026-09-08 确认编码工作只由一名有编码能力的员工完成，其他员工不共同修改代码；
- 用户确认文档和编码协作都属于 Milestone 15，但拆成两个可独立验收的任务单元；
- [产品重启说明](../../01-product/Product-Reboot.md#14-轻量多员工协作方向)、[MVP Plan Milestone 15](../MVP-Plan.md#22-milestone-15轻量多员工协作)、[Agent Runtime](../../03-core/Agent-Runtime.md#15-agent-间协作)、[M9 编码任务合同](M9-TU-01-coding-task-loop.md)和[简化与后续增强清单 DE-011、DE-023](../Deferred-Enhancements.md#de-011-从单员工扩展到多员工协作)。

## 2. 前置条件

- M15-TU-01 已完成并证明分工、交接、最终负责人和整体验收流程可用；
- M9-TU-01 的代码读写、系统命令、任务级授权、进程终止和成果登记继续可复用；
- M15 共用的公司协作入口、负责人选择、失败和取消行为已经获得用户确认并写入权威设计；
- 开始实施时重新记录准确 Git 基线和工作区已有修改；Windows 本机验证，macOS 由同一候选提交的 CI 补充。

## 3. 包含范围

- 一项编码协作任务允许同公司中的其他员工先提供要求整理、资料、测试建议或代码检查意见；
- 整项任务明确指定唯一编码员工，只有该员工可以修改代码、登记代码成果以及运行可能改变项目的命令；
- 其他员工通过应用内交接记录提供结果，可以读取明确分配的必要内容，但不能获得代码写入和项目命令能力；
- 编码员工接收交接结果，在用户选择的现有 Workspace 中完成修改、运行检查并交付真实成果；
- 检查员工提出问题后，修改仍交回同一编码员工完成，不切换代码写入负责人；
- 用户能看到参与员工、各自模型和 Skill、分工、交接、唯一编码员工、完整模型与工具过程、检查结果和最终成果；
- 使用一条真实编码任务验证从辅助分工、单人编码、命令检查、反馈修改到用户验收的完整流程。

## 4. 非范围

- 不创建 Git worktree、员工分支、临时仓库、补丁队列或自动合并流程；
- 不支持多名员工同时修改代码、轮流接管代码写入或分别提交可合并代码；
- 不建设通用代码审查平台、持续集成平台或多项目仓库管理；
- 不改变 M9 已确认的命令授权、高风险操作和无 OS 级强隔离事实；
- 不扩展新的编程语言、构建工具、系统环境或在线服务；
- 不在本任务中重做正式版 UI。

## 5. 简化与后续增强

- 本任务完成后才能与 M15-TU-01 一起关闭 `DE-011` 和 Milestone 15；
- 多编码员工并行修改、Git worktree、分支和合并保留在 `DE-023`，没有真实重复需求时不实施；
- 正式版 UI 继续由 Milestone 15 后的 `DE-022` 独立处理。

## 6. 依赖与接口

- 复用 M15-TU-01 的协作任务、分工、交接、最终负责人和整体状态；
- 协作运行上下文必须记录唯一编码员工 ID；可信 Main 侧只为该员工注册 Workspace 写入、脚本执行和项目命令工具；
- 其他员工的模型输出不能直接转成文件修改或命令调用，只能成为可见交接内容；
- 编码员工仍受任务保存的 Workspace、现有文件并发哈希、路径、敏感文件、命令授权、安装审批、取消和进程树终止规则约束；
- 真实代码差异、命令输出和成果登记继续由现有工具产生，不能使用模型总结冒充。

## 7. 交付物与所有权

专属修改区预计包括单一编码员工分派、工具能力裁剪、编码交接界面、专项 fixture、测试和证据。

共享冲突区包括 M15 协作协议与存储、Pi 任务运行、M9 Workspace/命令工具注册、成果、Renderer、UI 文档、E2E、`PROJECT_STATUS.md` 和 CI。实施时必须以 M15-TU-01 已冻结的接口为基线串行修改。
