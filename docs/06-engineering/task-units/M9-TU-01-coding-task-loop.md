## 1. 需求与设计引用

- 用户确认：不引入 `pi-coding-agent`，使用现有 Pi Agent Core、标准 Skill 和 AI Corporation 自管工具；编码通用工具、提示词和测试可以借鉴 `pi-coding-agent`；
- 用户确认：每个任务首条命令只确认一次，普通编码命令之后不反复确认，明显高风险命令仍单独确认；
- 用户确认：使用系统原生完整命令，允许管道、串联和重定向，不强制切换 PowerShell 或 Git Bash；
- 用户确认：命令可以在可信任务内以用户 OS 账户运行，接受当前没有 OS 级强隔离的残余风险；好用是第一原则，不增加妨碍正常编码的形式限制；
- [MVP Plan Milestone 9](../MVP-Plan.md#16-milestone-9单员工真实编码任务)、[Tool Runtime](../../05-infrastructure/Tool-Runtime.md)、[Policy Engine](../../05-infrastructure/Policy-Engine.md)、[Threat Model](../Threat-Model.md)、[核心用户流程](../../07-ui/Core-User-Flows.md)、[设计系统](../../07-ui/Design-System.md)和[UI 专项验收](../../07-ui/UI-Acceptance.md)；
- `pi-coding-agent v0.84.1` 固定来源：提交 `53fa77ccd8a279eb87e92294ef3687b03ff80112`，MIT License，来源仓库 `https://github.com/earendil-works/pi`。

## 2. 前置条件

- M8-TU-01 和 Milestone 8 已完成，工作区选择、目录查看、文本读取和安全文本写入可复用；
- 当前分支为 `codex/pi-reboot`，基线工作区无未识别改动；
- Pi 模型过程、工具过程、取消、失败、恢复和用户验收闭环可复用；
- 本机真实 DeepSeek Provider 只保存在应用本地，不进入 Git、命令环境、日志、截图或测试产物；
- Windows 在本机验证，macOS 由 CI 补充；自动命令测试只使用任务自己的临时项目和受控 Provider。

## 3. 包含范围

- 新增内置“编码任务”标准 Skill，指导员工先理解项目、做最小修改、运行对应检查并如实交付；
- 新增版本化 `workspace.run_command` 工具，输入为完整命令文本，使用当前平台系统原生命令解释方式，支持管道、串联和重定向；
- 命令固定绑定当前任务保存的工作区，默认工作目录为工作区；模型不能在工具输入中替换可信工作区根；
- 每个任务第一次启动命令前显示一次任务级授权，明确说明 OS 账户、工作区外访问可能和无 OS 级强隔离；拒绝时不启动进程，任务可继续修改要求或取消；
- 授权后普通查看、搜索、检查、测试和构建命令不重复询问；依赖安装、删除、Git 写操作、发布和其他明显高风险命令按完整命令单独确认；
- 命令环境保留正常编码所需的系统环境，但剔除 Provider API Key、Key Vault 内容、应用会话令牌和 AI Corporation 自己的认证秘密；
- 实时保存并显示命令原文、开始时间、stdout、stderr、耗时、退出码、完成状态、截断说明和错误；大输出采用明确的行数/字节上限，不能让界面卡死；
- 用户取消、命令超时、任务终止或应用退出时终止整个进程树；任务完成后不允许残留由本工具启动的后台子进程；
- 命令在应用崩溃时处于运行中，恢复后标记为 `UNKNOWN`，不自动重放，也不冒充失败或成功；
- 继续使用现有工作区文本工具修改代码并显示差异；根据真实编码需要补充精确文本替换和搜索，但不绕过原有路径、敏感文件和并发覆盖保护；
- 借鉴 `pi-coding-agent v0.84.1` 的通用实现时保留来源、版本和 MIT 许可证说明，并根据 AI Corporation 的任务授权、事件和恢复模型改写；
- 员工完成受控缺陷项目的真实修复并运行测试后等待用户验收，用户确认后任务才完成。

## 4. 非范围

- 不安装或运行 `pi-coding-agent`，不接入 Pi Extension、TUI、凭据、会话或包管理系统；
- 不承诺命令被限制在工作区内，不提供容器、虚拟机、低权限账户或 OS 级强隔离；
- 不自动安装依赖、删除文件、执行 Git commit/push、发布、付款或其他外部不可逆动作；
- 不做远程 SSH、开发容器、云端执行、常驻后台服务管理或无人值守定时任务；
- 不做多员工协作、附件、多模态、图片、视频、Office/PDF 专用工具；
- 不迁移或删除旧 Goal/Plan/M3 数据。

## 6. 依赖与接口

- `workspace.run_command` 使用独立、严格、版本化的通用命令 Schema，不复用 Provider、Chat 或 `pi-coding-agent` DTO；
- 输入至少包含命令文本；可信任务 ID、Workspace ID、工作区根、授权和超时由 Main 侧上下文提供，Renderer 与模型不能伪造；
- 输出至少包含调用 ID、状态、stdout/stderr 摘要、退出码、耗时、是否截断和标准化错误；流式事件带调用 ID 和单调序号，迟到事件不能覆盖终态；
- 授权状态只保存在当前任务范围，任务结束、取消或新建任务后失效；高风险命令批准绑定规范化完整命令指纹，批准 A 不能执行 B；
- 命令调用在启动进程前记录 `STARTING`；成功、失败、取消、超时和未知均持久化；未知不自动重放；
- 原生进程边界负责启动、流读取、超时和整个进程树终止；TypeScript 负责 Pi Tool、Policy、事件、持久化和 UI；
- 直接借鉴或改写的代码必须记录文件来源和固定版本，并在仓库第三方声明中保留 MIT 归属。

## 9. 隔离与干扰控制

- 自动测试使用 `M9-TU-01-<random>` 临时 userData、SQLite、Workspace、目录、端口、员工、任务和进程标记；
- 命令 fixture 只操作自己创建的临时项目，不读取或修改用户真实仓库、主目录、Key Vault、系统设置或外部服务；
- 进程树测试只启动带唯一标记的测试子进程，按 PID/标记核对并清理；不使用宽泛进程名结束其他任务；
- 删除、安装、Git 写操作和发布测试只验证策略，不执行真实高风险副作用；
- 自动模型测试使用假 Key 和本地受控 Provider；真实 DeepSeek 只在正式应用本地专项测试中使用；
- 命令和输出 fixture 不含真实秘密；Secret scan 覆盖环境、日志、数据库、截图和测试产物；
- migration 使用开始实施时下一未占用编号，并与其他任务串行。
