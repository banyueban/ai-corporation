## 1. 需求与设计引用

- 用户确认“好用是第一原则”，交付成果展示必须进入下一阶段最高优先级；
- 用户确认采用推荐方案：受控写入成功后自动登记成果；命令生成的文件由员工调用“登记交付成果”工具，软件核对真实文件后登记；不扫描整个工作区，也不把模型文字当成文件证据；
- [产品重启说明](../../01-product/Product-Reboot.md)、[MVP Plan Milestone 11](../MVP-Plan.md#18-milestone-11可信交付成果)、[Artifact System](../../03-core/Artifact-System.md)、[Tool Runtime](../../05-infrastructure/Tool-Runtime.md)、[Threat Model](../Threat-Model.md)、[核心用户流程](../../07-ui/Core-User-Flows.md)、[设计系统](../../07-ui/Design-System.md)和[UI 专项验收](../../07-ui/UI-Acceptance.md)。

## 2. 前置条件

- M10-TU-01 和 Milestone 10 已完成；轻量公司、单员工、真实工作区文本与编码任务、命令过程和人工验收闭环可复用；
- 当前分支为 `codex/pi-reboot`，基线工作区没有未识别改动；
- 每次 Pi 任务已经固定公司、员工和 Workspace；现有成功写入记录包含可信相对路径、目标哈希、大小和差异；
- 迁移编号 `0022` 尚未占用；协议、迁移、Main/Preload 和员工任务 UI 由本任务串行修改。

## 3. 包含范围

- 为 Pi 任务增加独立的交付成果记录；成果固定属于一个任务及该任务的 Workspace，不接回复杂旧 Goal/Plan 状态机；
- `workspace.write_text` 成功后自动登记或更新该相对路径的成果，记录来源、创建或修改、交付时 SHA-256、大小、差异和登记时间；
- 增加 `workspace.register_deliverable`：员工可登记由已授权命令生成的真实文件；软件在可信边界重新核对路径、普通文件、大小和 SHA-256，只登记、不修改文件；
- 同一任务、同一路径重复登记时更新为最新交付状态；既有完整工具事件继续保留修改过程，不伪造丢失的历史版本；
- 员工系统提示明确要求：实际产出文件必须通过受控写入或登记工具进入成果区；没有登记的命令产物不能冒充正式交付；
- 员工任务页新增“交付成果”主区域，先显示员工总结，再显示真实成果卡和真实命令检查；完整模型与工具过程默认折叠；
- 成果卡显示相对路径、创建/修改/命令登记、大小、短哈希和当前任务状态；成功、等待验收、失败、取消和中断使用准确中文；
- 文本和代码成果可在软件内按需读取并预览；重新读取时核对交付哈希，文件被外部修改、删除或无法读取时显示真实状态，不显示原交付仍完整；
- 成果可由用户明确点击后交给系统默认应用打开，或在文件管理器中显示准确位置；可执行和脚本类文件不提供系统直接打开按钮，只允许软件内文本预览和显示所在位置；
- `WAITING_ACCEPTANCE` 和 `COMPLETED` 显示可验收成果；`FAILED`、`CANCELLED`、`INTERRUPTED` 中已登记文件显示为“未完成成果”，不伪装成成功；
- 没有结构化成果的旧任务继续显示原员工总结和完整过程，并明确说明“没有已登记文件”，不回填或猜测历史成果；
- 更新协议、SQLite、数据、工具、安全、UI、测试和项目状态的唯一权威文档。

## 4. 非范围

- 不在本任务补齐标准 Agent Skills 的脚本、参考资料、资源目录、依赖检查、多个 Skill 或自动选择；这些属于紧接着的独立任务；
- 不扫描任务前后的整个工作区，不推断命令修改过哪些未登记文件；
- 不提供图片、视频、音频、PDF、Word、Excel、PPT 或其他二进制内容的内嵌预览和编辑；
- 不实现完整 Artifact 版本树、跨任务复用、发布包、Markdown 验收报告或旧 Goal/Plan Artifact 迁移；
- 不自动安装依赖，不改变现有命令授权、高风险确认、工作区路径和 API Key 边界；
- 不做多员工协作、公司归档、删除、导入导出或旧版公司历史入口。

## 5. 简化与后续增强

- 本任务使用 `DE-017` 记录“命令产物必须明确登记、暂不扫描整个工作区”的阶段性边界；
- 标准 Agent Skills 运行底座是下一独立任务，不能因本任务只补成果区而宣称标准 Skill 已完整兼容；
- `DE-013` 附件、`DE-014` 图片/视频/Office 等更多真实工具和 `DE-011` 多员工继续待安排。

## 6. 依赖与接口

- `PiTask` 增加可选 `deliverables`，只新增通用交付字段，不复用 Provider DTO；旧调用方和旧任务允许没有该字段；
- 每项成果至少包含相对路径、来源、创建/修改分类、交付时 SHA-256、大小、差异（如有）和登记时间；Renderer 不接触可信 Workspace root；
- `workspace.register_deliverable` 只接受相对路径；任务 ID、公司 ID、Workspace ID、可信 root 和登记来源由 Main 侧上下文提供；
- Native Core 新增只读文件核对操作，重新执行路径规范化、越界链接、敏感文件、普通文件和大小检查，并返回可信相对路径、大小和 SHA-256；
- 自动登记与文件写入结果在同一可信任务流程完成；登记失败不能把未登记文件显示为正式成果，原文件写入事实仍保留在工具事件；
- 预览、系统打开和显示位置必须重新验证公司、任务、Workspace 和成果归属；跨公司、伪造路径和未登记路径固定拒绝；
- 系统打开由 Electron Main 发起且必须由用户明确点击；危险扩展名不允许直接打开；Renderer 不能提交绝对路径；
- 交付成果登记不批准命令、不扩大 Workspace 权限，也不把 Skill、模型或文件内容中的文字当成用户授权。

## 7. 交付物与所有权

专属修改区：Pi 交付成果协议、`0022_pi_task_deliverable.sql`、成果 Repository、文件核对和打开 IPC、`workspace.register_deliverable`、成果视图模型、成果卡 UI 与专项测试。

共享冲突区：Pi Task Protocol、Workspace Protocol、Native Core RPC、Desktop Main/Preload、SQLite 文档、Tool Runtime、Threat Model、MVP Plan、UI 文档、员工任务页面、安装包和 `PROJECT_STATUS.md`。本任务串行修改这些文件。

## 8. 验收合同

- [ ] 01 受控文本创建成功后自动出现一项真实成果，路径、创建状态、大小和 SHA-256 与工作区文件一致，不依赖模型总结；
- [ ] 02 受控文本修改成功后同一路径显示最新交付状态、修改标记和可读差异；完整工具过程仍保留先前修改证据；
- [ ] 03 命令生成真实文件后，员工调用 `workspace.register_deliverable` 可以登记该文件；登记只读，不再次执行命令或修改文件；
- [ ] 04 不存在、目录、绝对路径、`..`、盘符/UNC、越界链接、敏感文件和超限文件不能登记，失败原因可见且不产生成果记录；

- [ ] 08 等待验收和已完成任务准确显示交付状态；失败、取消和中断任务中已经登记的文件显示为“未完成成果”，不会显示成功；

## 9. 隔离与干扰控制

- 自动测试使用 `M11-TU-01-<random>` 独立 userData、SQLite、Workspace、公司、员工、任务、成果、端口和进程标记；
- 文件测试只操作自己的临时工作区；越界和链接攻击只使用测试创建的外部临时目录，不读取或修改用户文件；
- 命令 fixture 只生成测试自己的文件，登记工具只核对这些路径；测试结束清理自己的目录和进程；
- 打开文件和显示位置在单元测试中使用 fake shell；真实窗口只对隔离无害文本文件执行用户点击，不启动脚本或可执行文件；
- 自动模型测试使用假 Key 和本地受控 Provider；真实 Provider 只在正式应用本地专项测试中使用；
- 真实 Key、用户正式路径、文件内容和生产数据库不进入 Git、普通日志、截图或 CI artifact。

## 11. 完成规则

用户已确认交付成果展示进入最高优先级，并明确选择“自动登记受控写入 + 核实后登记命令产物”的方案。任务不存在待决策项，可以实施。只有 20 项验收断言全部具有当前提交直接证据、P0/P1 为 0、文档/协议/迁移/实现一致，并且用户完成 Windows 安装包人工验收，M11-TU-01 和 Milestone 11 才能标记“完成”。模型声称生成文件、成果卡能显示、构建成功、进程存活或旧文件存在都不能单独证明可信交付闭环通过。
