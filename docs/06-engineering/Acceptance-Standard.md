# AI Corporation Desktop v0.1 统一验收标准

| 属性 | 值 |
|---|---|
| 文档角色 | 规范性 |
| 权威范围 | 通用 Definition of Done、验收层级、证据充分性、缺陷等级和发布总门槛 |
| 文档地位 | 项目唯一验收入口 |

## 1. 目的与优先级

所有任务、功能、Milestone 和发布候选都从本文档进入验收。具体产品断言、测试方法、安全边界和 UI 场景仍由专项文档定义，本文档不复制其细节。

冲突优先级：

1. 安全硬限制；
2. 已确认的用户目标和 PRD 产品范围；
3. 领域不变量、跨模块协议和数据约束；
4. 本文档的完成、缺陷与证据规则；
5. 模块内部设计和 UI 展示建议。

低优先级约束不得降低高优先级要求；无法消解时停止相关交付并请求决策。

## 2. 验收层级

```text
L1 变更/任务单元
→ L2 完整功能
→ L3 Milestone
→ L4 发布候选
```

- **L1**：验证一个任务合同内的代码、文档、Schema、迁移或测试断言；
- **L2**：验证用户可感知的完整能力和正常/异常/恢复/安全路径；
- **L3**：验证 MVP Plan 对应 Milestone 的交付物、演示和回归；
- **L4**：验证最终安装包、跨平台、数据、安全、UI 和发布证据。

低层通过不自动代表高层通过。任务单元只证明其合同内断言，格式和关闭规则见[任务单元规范](Task-Unit-Standard.md)。

## 3. 项目级 Definition of Done

一个交付只有同时满足全部适用条件，才能标记“完成”。

### 3.1 范围与设计

- [ ] 结果对应用户目标、PRD 或当前任务合同；
- [ ] 范围内、非范围、假设和约束明确；
- [ ] 没有静默扩大产品、Milestone 或任务边界；
- [ ] 实现符合架构、领域不变量和唯一协议；
- [ ] 状态机、错误、权限、预算、恢复和并发行为没有被临时绕过；
- [ ] 重大偏离已记录影响并获得确认。

### 3.2 实现与数据

- [ ] 实现完整、可读，不以占位逻辑冒充结果；
- [ ] 正常、异常、取消、超时、重试和恢复路径按适用范围处理；
- [ ] 数据约束、迁移、事务、幂等和并发策略与设计一致；
- [ ] 协议、Schema、枚举和持久化映射同步；
- [ ] 未引入无关改动、凭据、调试残留或生成物污染。

### 3.3 安全与隐私

- [ ] 满足[威胁模型](Threat-Model.md)中适用安全门槛；
- [ ] Renderer、插件、模型输出和外部内容保持不可信；
- [ ] 文件、进程、网络、凭据和破坏性操作遵守最小权限与审批；
- [ ] 日志、错误、Trace 和 Artifact 不泄露 Secret、敏感路径或用户文件内容；
- [ ] 安全拒绝、审批失效和恢复未知状态有直接测试。

### 3.4 UI/UX

涉及用户界面时：

- [ ] 遵守[UI/UX 文档中心](../07-ui/README.md)路由的流程、信息架构、状态和设计系统；
- [ ] Loading、Empty、Error、Disabled、Offline/Degraded 和恢复状态按适用范围存在；
- [ ] Approval、Recovery、预算耗尽和验收失败显示精确资源、风险、证据与后果；
- [ ] 通过[UI 专项验收标准](../07-ui/UI-Acceptance.md)中适用场景；
- [ ] 可访问性、键盘、缩放和窗口尺寸要求有证据。

### 3.5 文档与运行

- [ ] 受影响的权威文档、协议、Schema、迁移和测试与实现一致；
- [ ] `PROJECT_STATUS.md` 只记录当前事实；
- [ ] 安装、运行、测试和恢复方式可重复；
- [ ] 已知限制、未执行验证和补验方式明确。

## 4. 功能验收

### 4.1 验收来源

按任务选择权威来源：

| 断言类型 | 权威来源 |
|---|---|
| 产品行为和用户场景 | [PRD](../01-product/PRD.md) |
| Milestone 范围和演示 | [MVP Plan](MVP-Plan.md) |
| 当前实施边界 | 当前任务合同 |
| 跨模块数据合同 | 对应 Protocol |
| 模块行为和恢复 | 对应 Core 文档 |
| 物理数据约束 | [Data Model](../05-infrastructure/Data-Model.md)与[SQLite Schema](../05-infrastructure/SQLite-Schema.md) |
| 安全行为 | [Threat Model](Threat-Model.md) |
| UI 行为 | [UI 文档中心](../07-ui/README.md)与[UI Acceptance](../07-ui/UI-Acceptance.md) |

### 4.2 功能断言格式

每条验收断言必须包含：

```text
Given：前置状态和 fixture
When：用户或系统动作
Then：可观察结果
And：状态、事件、Artifact、权限或副作用约束
Evidence：命令、报告、截图、日志片段或 CI job
```

正常、异常、安全、恢复和平台断言按功能风险选择。没有可观察结果或证据计划的条目不得作为“就绪”任务合同。

## 5. 测试与证据

测试层级、Mock/Fake 规则、跨平台矩阵和具体方法只由[测试方案](Testing-Strategy.md)定义。正式命令以仓库脚本和当前任务合同为准。

### 5.1 必检原则

- 变更必须有同层级测试，不能只依赖更低层或相邻功能测试；
- 协议、迁移、状态机、安全、恢复、并发和跨平台差异不得只测正常路径；
- 当前任务使用独立 fixture、临时目录、数据库、端口和进程生命周期；
- 源码 E2E 不能代替打包产物 E2E；
- 构建成功不能代替启动成功；
- 进程存活不能代替窗口可用和关键状态可达。

### 5.2 可接受证据

- 测试命令、退出码和摘要；
- CI run/job、平台、提交 SHA 和对应 artifact；
- 测试报告、截图、录屏、结构化 Trace 或数据库断言；
- 目标文件、Schema、迁移、哈希和静态检查结果；
- 人工检查项、环境和结果记录。

以下不构成充分证据：

- 模型自评或“代码看起来正确”；
- 只说明“应该可以”；
- 只展示生成代码或未执行命令；
- 用其他任务、其他提交或其他交付层级的证据代验；
- 隐藏失败输出，只摘取局部成功。

无法执行必检项时必须记录原因、影响、风险、替代证据和补验方式；补验前只能标记“部分完成”或“阻塞”，不能标记“完成”。

## 6. 缺陷等级与门槛

本文档是缺陷等级的唯一解释来源。专项文档只能给出示例，不得重新定义等级。

| 等级 | 定义 | 门槛 |
|---|---|---|
| **P0** | 未授权副作用、数据损坏/不可恢复丢失、凭据或敏感数据泄漏、关键安全边界失效 | 阻止任务完成、Milestone 关闭和发布 |
| **P1** | 核心闭环不可完成、恢复产生重复副作用、关键权限/审批失效、目标平台关键路径不可用 | 阻止对应功能、Milestone 和发布 |
| **P2** | 重要但有明确可接受绕行方案，不破坏数据和安全边界 | 必须登记负责人、影响和处理计划 |
| **P3** | 轻微视觉、文案或低影响体验问题 | 可延期，但必须登记 |

适用必检项失败、关键安全边界未验证或交付物/证据不完整，与未解决 P0/P1 具有同等阻断效果。

## 7. Milestone 与发布门槛

### 7.1 Milestone

Milestone 只能在以下条件全部满足后关闭：

- [ ] MVP Plan 对应交付物和演示通过；
- [ ] 所有必需任务单元完成；
- [ ] Windows/macOS 适用检查通过；
- [ ] 相关测试、安全和 UI 证据完整；
- [ ] P0/P1 为 0，P2/P3 已登记；
- [ ] 回归、恢复和升级路径按适用范围通过；
- [ ] `PROJECT_STATUS.md` 与当前事实一致。

### 7.2 发布候选

发布候选还必须满足：

- [ ] PRD 产品级必过场景和成功指标达到目标；
- [ ] 最终安装包在目标平台直接启动并完成关键路径；
- [ ] 数据迁移、备份、恢复和卸载行为通过；
- [ ] Threat Model 的发布安全门槛全部通过；
- [ ] UI-AC-01 至 UI-AC-07 的适用场景通过；
- [ ] 发布产物、Rust Sidecar、版本和哈希可验证；
- [ ] 发布说明、已知限制和未解决 P2/P3 完整；
- [ ] 应用签名、notarization 等公开发布前置条件满足。

## 8. 状态用语

Codex 和项目成员只能使用：

- **未开始**：尚未进入合同就绪或实施；
- **就绪**：范围、依赖、接口和验收合同完整，可以实施；
- **进行中**：正在实施或验收；
- **完成**：全部适用验收通过，证据齐全；
- **部分完成**：已有成果，但仍有未通过验收项；
- **阻塞**：缺少权限、环境、决策或外部条件，无法继续；
- **失败**：实现或验收未达到要求，需要返工。

禁止使用“基本完成”“应该完成”“大概可用”等模糊状态。

## 9. 验收报告

最终交付至少包含：

```text
任务单元：
结果：
实现内容：
需求与设计引用：
验证证据：
未执行验证：
缺陷与已知限制：
下一步：
```

任务单元通过只关闭自身，不自动代表完整功能、Milestone 或发布候选通过。
